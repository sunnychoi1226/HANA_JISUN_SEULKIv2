# 호텔 견적 통합솔루션 v39

## V39 가격 우선 추천 개선

1. 기준 공개가(Benchmark Rate) 저장
- 호텔별 기준 공개가를 기준 객실명·숙박일·체크아웃일·성인 2명·1실·식사·세금 포함 여부·출처·조회일과 함께 저장
- 추천 카드에서 `기준요금 입력/수정`으로 직접 저장 가능
- 추천 카드의 기준요금 정보에 실제 조회 객실명을 함께 표시
- Supabase `hotel_benchmark_rates`에 이력을 유지하고, 가장 최근 확인값을 추천에 사용

2. 가격을 추천 선행 필터로 변경
- 가격 비중을 35점에서 50점으로 확대
- 목표예산 이내 50점 / +10% 이내 40점 / 사용자가 정한 허용범위 이내 25~40점
- 허용 예산 초과는 가격점수 0점이며 `예산 초과 참고 후보`로 후순위 처리
- 목표예산의 150% 이상은 `추천 제외` 처리
- 기준요금 미확인 호텔은 가격점수 5점만 부여하고, 가격 확인 호텔보다 뒤에 표시
- `예산 초과 후보 숨기기`를 기본값으로 적용

3. 설치
- 기존 Supabase 설정 후 `SUPABASE_V39_BENCHMARK_RATES.sql`을 추가 실행
- 배포 패키지에는 `netlify/functions/benchmark-rates.mjs`와 `public/price-scoring.js`가 포함되어야 함

4. 검증 기준
- 다낭 목표예산 USD 110 / 허용초과 20%에서 USD 330~390 기준요금 호텔은 가격점수 0점, 추천 제외
- 기준요금이 없는 호텔은 상위 추천으로 확정하지 않고 `기준요금 확인 필요`로 구분

## V38 핵심 보완

1. 내부 견적 이력 표시
- 추천 호텔 카드에서 `내부 견적 이력 N건`을 직접 표시
- 기존 점수의 `검증·내부 이력` 항목과 함께 사용자가 이력 존재 여부를 바로 확인 가능

2. 회신 자동 파서 신뢰도 개선
- 자동 추출 결과를 `확정 조건 / 조건부 / 확인 필요` 3개 영역으로 분리
- `if`, `with minimum`, `subject to` 등 조건부 표현은 조건부로 구분
- `please advise`, `please confirm`, `whether` 등 요청/문의 표현은 확인 필요로 구분
- 객실 라인의 뒤쪽 조건 문구는 객실명에서 분리해 비고/조건으로 이동
- 추출 결과는 Supabase `quotes.quote_terms` JSONB에 저장

3. 견적 비교 고도화
- 금액 외에 아래 조건을 호텔별로 나란히 비교
  - 객실타입 / 객실 수 / 박당요금
  - Resort Fee
  - FOC
  - Rebate
  - Seminar
  - F&B / Dinner
  - 취소조건
  - 총액 / 1인당 / 옵션기한
