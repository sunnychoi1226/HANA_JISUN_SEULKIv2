# 인센티브 호텔 추천·견적 시스템 v28

## V28 수정 목적

V27에서 확인된 두 가지 문제를 수정한 버전입니다.

1. 주요도시를 입력해도 중심 지도가 즉시 이동하지 않는 문제
2. 괌 추천 시 검증 캐시를 읽지 못하고 검색 오류가 발생하는 문제

## 핵심 수정

- 주요도시 39개는 브라우저 내 공개 좌표를 사용해 Supabase/외부 API와 무관하게 즉시 지도 이동
- `ensureMap()` / `moveMapToCity()`를 추가해 지도 초기화 시점에 관계없이 중심 위치 적용
- 지도 마커에 좌표가 없는 호텔은 건너뛰어 전체 결과 렌더링이 중단되지 않도록 처리
- 성급이 소수/문자형으로 들어와도 별점 렌더링 오류가 나지 않도록 방어 처리
- 검색 단계를 `지도 → 내부 Master → 검증 캐시 → 신규 외부검색` 순으로 화면에 표시
- 괌은 검증 캐시가 이미 구축되어 있으므로 캐시 조회 실패 시 외부검색으로 넘어가지 않고 Supabase 연결 오류를 명확히 표시
- 신규도시/미캐시 도시만 외부검색 실행
- 각 조회에 타임아웃을 적용해 장시간 `검색 중` 상태로 남지 않음

## Supabase Secret Key 중요 수정

Netlify 환경변수 `SUPABASE_SERVICE_ROLE_KEY`에 `sb_secret_...` 형식의 신규 Secret key를 넣은 경우,
V28부터는 Supabase REST 호출 시 해당 키를 `apikey` 헤더로만 전송합니다.

신규 Secret key는 JWT가 아니므로 `Authorization: Bearer sb_secret_...` 방식으로 보내지 않습니다.

기존 legacy service_role JWT(`eyJ...`)를 사용하는 경우에는 기존 방식대로 Authorization Bearer 헤더도 추가합니다.

## 괌 테스트

1. 로그인
2. 지역 `남태평양`
3. 도시 `괌` 입력
4. 입력 후 약 0.25초 내 중심 지도가 괌으로 이동하는지 확인
5. `호텔 추천 보기`
6. 화면 진행 문구 확인:
   - `1/3 괌 지도 표시 완료`
   - `2/3 내부 Master ...개 확인`
   - 검증 캐시 확인
7. 정상 완료 시:
   - 괌 저장 캐시 약 20개
   - `실시간 외부검색 없음`
   - 호텔별 객실수 / 연회장 / 미팅룸 / 검증 태그 노출

## 배포 방법

GitHub 저장소의 기존 앱 파일을 V28 파일로 교체 후 Commit합니다.
Netlify와 GitHub가 연결되어 있다면 자동 재배포됩니다.

Supabase 데이터는 이미 구축되어 있으므로 별도 SQL 실행은 필요하지 않습니다.
Netlify의 기존 환경변수도 바꿀 필요 없습니다.
